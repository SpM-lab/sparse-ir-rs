# Python 3.14 support

## Summary

Prepared `pylibsparseir` for CPython 3.14 on PyPI and conda, and aligned the
workspace for the next release.

## Investigation

- Confirmed that the 0.8.4 PyPI release only provides CPython 3.10--3.13
  wheels, although the package metadata allows Python 3.14.
- Ran the Python test suite with CPython 3.14. The real-valued C API tests
  passed, while complex-valued tests exposed a name collision: Python 3.14's
  `ctypes` exports `c_double_complex`, and `ctypes_wrapper` leaked it through
  wildcard imports, replacing the binding's ABI-compatible structure type in
  callers.
- Checked the changes since v0.8.4. Because current `main` includes
  backward-compatible public Rust API additions, the repository's SemVer
  policy selects 0.9.0 rather than a patch version.

## Decisions

- Restricted `ctypes_wrapper.__all__` to binding-owned names so Python 3.14's
  new `ctypes.c_double_complex` cannot shadow the binding type.
- Added CPython 3.14 to direct tests and to Linux and Apple Silicon wheel
  builds. Free-threaded `cp314t` wheels remain outside this change.
- Added Python 3.14 to the conda variants. NumPy versions older than 2.3 are
  skipped for Python 3.14 because they do not provide compatible packages.

## Verification

- CPython 3.14: `uv sync --python 3.14 --locked` and the complete Python test
  suite (64 passed).
- Version consistency: `python3 check_version.py`.
- Packaging: `uv build --wheel` from `python/`; the resulting artifact was a
  `cp314-cp314` macOS ARM64 wheel and was installed in a clean environment.
- Hosted CI remains responsible for the Linux wheel matrix and conda builds.
- Confirmed that conda-forge provides Python 3.14, NumPy 2.3, and SciPy 1.16
  packages for the Linux x86-64 and macOS Apple Silicon build targets.

## Remaining risks

- The existing sdist does not contain the parent Rust workspace, so rebuilding
  a wheel from that sdist fails. PyPI currently publishes platform wheels only;
  correcting the sdist layout is separate packaging work.
- The conda recipe was syntax-checked locally. Hosted conda CI owns solving and
  building the complete Linux/macOS variant matrix.
